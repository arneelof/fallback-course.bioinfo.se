How to run it

  1. Start clean, the students' way. Open the notebook from the link above, which is the link the students get: it opens in VS Code and runs on a Colab machine through the Google Colab extension (see the Setup page; following it is part of the test for Lab 2). Connect to a new Colab runtime, with the runtime type a student would use (CPU unless the notebook says GPU), and do not reuse files from an earlier run.
  2. Work as a student. Read the instructions, fill in every todo(...) yourself and answer the questions in the quiz preview from your own output. Do not look at a solution first.
  3. Time it. Write down the clock time when you start, when you start each part (A, B, C, ...) and when you finish. Include the time spent reading and thinking, not only the time the cells run.
  4. Note what goes wrong. Every cell that fails (with the first line of the error), every cell that takes more than about two minutes, and every web service that is slow or down (NCBI, EBI, UniProt, PDB, Foldseek, the AlphaFold Server, ...).
  5. Write down your numbers. For every question with a numerical or exact answer, the value your run gave. We compare them with the answer keys, so you do not need the keys. One run is enough.
  6. Note what was unclear in the instructions or the questions, and anything that took much longer than it should have.

How to report it

Email the notes to arne@bioinfo.se (and to Petras for Labs 3-6). A plain list in the mail is enough; we sort it out from there.

If you would rather keep it structured, fill in your lab's row in tools/canvas/dry-run.csv in the course repository, which already has one row per lab with its responsible TA (see Editing the course files below). The columns are: lab, your name, date, runtime type, minutes per part, total minutes, failed or slow cells, services that were slow or down, your numbers, what was unclear, other comments. If another TA runs the same lab later, that goes on a new line. If git does not work for you, fill in the template dry-run-template.csv and email it to arne@bioinfo.se. The same deadline holds for your feedback on the session's lecture.

Editing the course files

The TAs edit two files in the course repository github.com/arneelof/BioinfoCourse (private: ask Arne if you cannot open it) directly: tools/canvas/dry-run.csv for the lab dry runs and tools/canvas/schedule.csv for the room bookings.

  1. The simplest way is GitHub's web editor: open the file on GitHub, click the pencil (Edit this file), make the change, and click Commit changes on main with a short message such as "Lab 5 dry run" or "Room for the orals on 24 March". With a clone, git pull first, then commit only the file you changed and push.
  2. Room bookings: in schedule.csv, find the event's line (the ones still to book say To be booked in the room column), replace To be booked by the room's name, and correct the start and end time if the booking differs. If an event needs two rooms or two slots, copy the line and change the copy. Leave the other columns and lines as they are.
  3. CSV rules: one line per entry, columns separated by commas; a field that contains a comma must be in double quotes; several names in one field are separated by ;; names are written exactly as in tools/canvas/people.csv; dates as 2027-03-24 and times as 13:00.

The site is not updated automatically: Arne checks the changes and deploys them, and the Canvas schedule, the course calendar and the TA workload table are rebuilt from schedule.csv.
