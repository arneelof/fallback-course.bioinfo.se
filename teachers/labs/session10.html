When does a convolution make sense?

A convolutional layer slides the same small set of weights along a grid (pixels, residues, nucleotides, voxels), so it assumes that neighbouring positions belong together and that the same local pattern means the same thing wherever it occurs.

Section 2: dense vs. convolutional, counting weights

The dense model is Flatten → Linear(2352, 10) → Tanh → Linear(10, 8). The convolutional model is Conv2d(3, 10, kernel_size=5) → Tanh → Flatten → Linear(5760, 8). Count layer by layer first: a dense layer has inputs × outputs weights plus one bias per output; a convolutional layer has kernel height × kernel width × input channels × filters weights plus one bias per filter, however large the image is. Only then add up the whole model: the dense layer after a convolution depends on the size of the feature map it receives.

Section 3: what do the weights buy?

Four networks, each trained for 10 epochs with Adam: two dense networks (10 tanh units, and 128 tanh units), the one-layer convolutional network, and a small CNN of two convolutional blocks (16 and 32 filters of 3×3, each followed by ReLU and 2×2 max pooling).

Question 4 · choose all that apply · 1 point

Which statements match your table and plot? (More than one answer can be correct.)

  • The small CNN is the most accurate of the four networks, although it has the fewest parameters (about 17 times fewer than the 128-unit dense network)

  • The 128-unit dense network fits the training images much better than the validation images (training accuracy about 0.93–0.97, validation about 0.77–0.82), so its extra weights mostly go into memorising the training set

  • A dense layer must learn a separate weight for every pixel position and colour, while a convolution reuses the same small filter everywhere, so the CNN needs far fewer examples per useful pattern

  • Adding more dense weights closes the gap to the CNN: 300,000 weights reach the same accuracy as the small CNN

  • The CNN wins only because it was trained for more epochs

Question 7 · choose one · 1 point

What is padding in a convolutional layer, and why might we need it?

  • It changes the activation function applied after the convolution

  • It removes the border pixels, to make the convolution faster

  • It adds extra values (usually zeros) around the input, so the kernel can also be centred on edge pixels and, if chosen right, the output keeps the input’s size

  • It increases the number of filters, to give the model more capacity

Section 5: VGG blocks and cells in unexpected places

Question 9 · choose one · 1 point

What happens when the VGG networks (1 or 3 blocks) are trained on corner cells and validated on randomly placed cells?

  • One VGG block already reaches more than 0.8 accuracy on the randomly placed cells

  • One block fails, but three blocks reach more than 0.8

  • Both reach well above 0.7 on corner cells but only roughly 0.15–0.3 on randomly placed cells, about as good as always guessing the most common class: no architecture works for this combination of training and test data

  • Both reach the same high accuracy on corner and random cells, because convolution is translation-invariant

Question 10 · choose one · 1 point

Convolution is translation-equivariant: a shifted cell gives shifted feature maps. Why does the network still fail on cells at new positions?

  • The final Flatten + Linear layer gives every position its own weights, and those weights were only ever trained on features in the bottom-right corner; two or three 2×2 poolings add only a few pixels of tolerance

  • Convolutional layers are not equivariant when padding is used

  • The validation images were standardised with different statistics

  • Max pooling removes all position information, so the network cannot see the cell at all
