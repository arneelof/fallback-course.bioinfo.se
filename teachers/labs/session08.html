The data are BloodMNIST (MedMNIST v2, Yang et al. 2023, CC BY 4.0): microscope images of single blood cells, 28×28 colour pixels, in eight classes. The lab uses a fixed subset of 4,000 training, 1,000 validation and 2,000 test images.

Question 3 · choose one · 1 point

Basophils make up 6.7% of the training images. A model that never predicts “basophil” can still reach a high accuracy. What does this say about accuracy as a summary for these data?

  • Nothing: accuracy treats every class equally, so a missed rare class costs as much as a missed common one

  • Accuracy counts images, not classes, so a rare class barely moves it: a model can ignore basophils completely and lose at most 6.7 percentage points. Per-class recall (or the confusion matrix) is needed to see that

  • Accuracy is only misleading for binary classification

  • The classes are perfectly balanced, so accuracy is the right summary

Question 4 · choose one · 1 point

The notebook standardises each colour channel (subtract the mean, divide by the standard deviation). Why are the means and standard deviations computed on the training images only, and then applied unchanged to the validation and test images?

  • Because the validation and test images have no pixels

  • Because computing them on all images would give exactly the same numbers anyway

  • Using validation or test images to set preprocessing lets information from them leak into the model, so their accuracy would no longer be an honest estimate for new data

  • Because PyTorch cannot standardise more than one data set

Question 9 · choose one · 1 point

For “immature granulocyte vs rest”, the accuracy of the yes/no call ((TP + TN) / 1000) comes out clearly higher than the precision. Why?

  • Precision is computed incorrectly by sklearn

  • About 830 of the 1,000 validation images are not immature granulocytes, and most of them are correctly called “not IG”, so true negatives dominate the accuracy; precision only looks at the images the model called IG, where about half are wrong

  • Accuracy ignores true negatives

  • Precision is always lower than accuracy

Section 8: how much data does the model need?

The same model is retrained on stratified subsets of 100 and 1,000 training images and on all 4,000, always evaluated on the same 1,000 validation images.

Question 11 · choose one · 1 point

What happens to the gap between training and validation accuracy as the training set grows from 100 to 4,000 images?

  • The gap grows: more data makes overfitting worse

  • The gap shrinks: with 100 images the model does far better on its own training images (about 0.8) than on the validation images (about 0.5), while with 4,000 images the two are only about 0.05 apart

  • The gap stays the same, because the model does not change

  • Training accuracy drops below validation accuracy for every size

Question 13 · choose one · 1 point

Why is the test set used only once, and only at the end?

  • The test set is too large to evaluate twice

  • Every choice guided by a data set (here, the training-set size) makes that set optimistic. The test set must not guide any choice, so that it remains an honest estimate of performance on new images

  • Evaluating a model changes its weights

  • Because the test images are not standardised

Section 9: back to proteins, homology leakage

Session 8’s 700 localisation proteins, clustered with MMseqs2 at 30% identity (precomputed). The notebook makes a plain random 70/15/15 split and checks, for each validation protein, whether a member of its cluster is in the training set. (The proteins are fetched live from UniProt, so this number can drift slightly if UniProt’s annotations change.)

Question 14 · number · 1 point

What percentage of the 105 validation proteins have a ≥30%-identity homolog in the training set, with this random split?

Question 15 · choose one · 1 point

What does this mean for a localisation classifier evaluated on that random split, and what is the fix?

  • Nothing: homologs are different proteins, so they are independent examples

  • For those proteins the model can score well by recognising the protein family rather than the localisation signal, which inflates the validation accuracy. The fix is homology partitioning: cluster first, then keep whole clusters on one side of the split

  • The model will be less accurate on those proteins, so the estimate is too pessimistic

  • The fix is to use a larger random validation set
