Dynamic programming, interactively

A draft for comment, not yet part of the course

NoteWhat this is

A working draft of an interactive dynamic-programming matrix, written for Sessions 4 and 5. It is not linked from the course notes and not in Canvas. This page exists so that it can be looked at and argued with before it goes anywhere students can reach.

The same widget already supplies the matrix figures on the Session 4 slides: every matrix in block 2 of that deck is a screenshot of what is below, so the projector and this page cannot drift apart.

Why bother

The matrix is the one thing in Session 4 that every student has to be able to fill by hand, and it is the thing a static figure teaches worst. A figure can assert that three candidates were compared and the largest kept. It cannot let anyone get it wrong and find out why.

Three ways of using it, from watching to doing, and then the same two sequences run twice more with one thing changed each time: first the scoring, then global for local. The lecture walks the same three passes.

1 · Step through it

The blue cell is the one being decided. The three yellow cells are the only ones it is allowed to look at, and each carries a badge with the value it offers; the winning offer is green. That green badge is the max in the recurrence, happening where the room can see it.

\[V(i,j) = \max \begin{cases} V(i-1,j-1) + s(x_i, y_j) \\ V(i-1,j) + g \\ V(i,j-1) + g \end{cases}\]

The two sequences are protein fragments, scored for now by plain identity: match \(+1\), mismatch \(-1\), gap \(-1\). Protein letters from the start, because Sessions 4 and 5 are about proteins, and because the same two sequences come back below under BLOSUM62 and then locally, with one thing changed at a time. They are pieces of HEAGAWGHEE and PAWHEAE, the pair the textbooks use.

2 · Guess the next value

Everything above and to the left is filled in already. Work out the blue cell and type it. Whether the answer is right or wrong, the full max(...) is shown afterwards, and the widget says so when two predecessors tie, which is the point students most often miss.

3 · Fill the whole matrix

Every cell is yours to type. Check the matrix marks each one, and the traceback and the alignment appear once the grid is right. This is the lab exercise, done in a browser rather than on paper, and marked instantly.

4 · The same letters, a real substitution matrix

Nothing below has changed except the scoring: the same AWGHE against AWHEA, now with BLOSUM62 and a gap of \(-8\) instead of match/mismatch.

Identity scoring bought two gaps to chase exact matches and returned AWGHE- against AW-HEA, score \(2\). BLOSUM62 knows that G against H and E against A are substitutions a protein tolerates, and that neither is worth a gap at \(-8\), so it drops both gaps and returns AWGHE against AWHEA, score \(12\). Same letters, same algorithm, different answer — which is the argument for substitution matrices, made on a matrix small enough to check by hand.

5 · The same letters again, local instead of global

One more change, and again only one: a floor of zero, which is all that separates Smith–Waterman from Needleman–Wunsch.

The zero is a fourth candidate and gets a badge of its own in the cell being decided, which is the only place local differs from global and the thing a static figure cannot show. The traceback now starts at the best cell anywhere in the grid rather than the bottom-right corner, and stops at the first zero, giving AWGHE against AW-HE, score \(20\): the ragged ends are dropped and the conserved core is left. That is the answer the textbooks give for the full HEAGAWGHEE / PAWHEAE pair these fragments came from.

It is not only Session 4

Viterbi is the same recurrence with max-plus over log probabilities, so the profile-HMM half of Session 5 is a fourth mode rather than a second program.

Try your own

Everything above is fixed, so that the prose can describe it. This one is not.

Type a pair of sequences, or set a length and press New pair — the second sequence is a mutated copy of the first rather than an independent draw, because two random strings align into noise and teach nothing. Switching Alphabet between DNA and Protein also switches the scoring, since match/mismatch on protein wastes the demonstration and BLOSUM62 on four nucleotides is meaningless. Gap cost, global or local, and the mode can all be changed without losing the sequences.

Anything on this page can be set in the same way from a session page: the settings bar is one flag on the call, so a chapter can show a fixed example while the lab lets students change it.

What we would like to know

  1. Does it belong in the lecture, the lab, or only the notes? The slides already use it as a build-up. Whether a live demo is worth the minutes it costs in the room is a different question.
  2. Is one pair run three times the right shape? AWGHE against AWHEA is small enough to do in the room, and the notes now work the same three passes, so the lecture, this page and Session 4 all show one example. The cost is that nothing here is DNA any more.
  3. For Session 5, is BLOSUM62 with a linear gap enough, or does the affine gap need to be visible too? Affine means three matrices, and three matrices on one screen may teach less than it shows.

Provenance

Written for this course, from the recurrence, in plain JavaScript with no dependencies. Lukas Käll’s alignviz (Apache-2.0) does the stepping well and is worth a look, but it is a Streamlit server with no substitution matrix and no answer checking; nothing here is derived from it.
