Setup: VS Code, and Colab when you need a GPU

A lab is one file, which you download and open on your own computer. Each lab’s page and its Canvas quiz have a download link; clicking it saves sessionNN-lab.ipynb to your machine, and you open it in VS Code. Nothing is cloned, and the notebook fetches the data it needs by itself, so there is nothing else to download.

Your work stays on your own computer, in that file. Keep it somewhere you will find it again, and keep it under version control once Session 2 has shown you how.

When a lab needs a GPU — mainly Sessions 9–12 — you do not move anywhere else: with the notebook open in VS Code, choose Select Kernel → Colab, and the code runs on a free Google machine while you keep editing in your own editor. Part 3 sets that up. This is how notebooks are used in research, which is why the course works this way.

What you need Why
VS Code on your laptop, with the extensions Jupyter and Python (both by Microsoft) To open, edit and run a lab notebook
The Google Colab extension (by Google) and a Google account Only to run a lab on a GPU, from inside VS Code (Sessions 9–12)
Optional: git To keep your own work under version control (Session 2), and to get all the course notebooks in one go if you want them

All notebooks fetch their data from the course’s GitHub repository, so they run the same way on any machine. Before the first lab in Session 2, do Parts 1 and 2: download a lab, open it, and check that its first cells run, so that the lab time is spent on the lab.

Part 1: Install VS Code and the extensions

  1. Install VS Code, and git if you do not already have it.
  2. In VS Code, open the Extensions view (Ctrl+Shift+X, or Cmd+Shift+X on a Mac) and install Python and Jupyter (both by Microsoft), and Google Colab (by Google) for the GPU labs.
  3. Check that you can sign in to Google in a browser with the account you want to use for the course.

Part 2: Download a lab and open it

  1. On the session page, or in the lab’s Canvas quiz, click the link to sessionNN-lab.ipynb. Your browser saves the file, normally to your Downloads folder. Move it somewhere you keep your coursework.

  2. Open it: in VS Code, File → Open File…, and choose the notebook. (Any editor that opens .ipynb files works; VS Code is what the course supports.)

  3. Run the cells from the top. The first cells install the few packages that are missing and download the lab’s data. If VS Code asks which kernel to use, pick your local Python — or Colab, if the lab needs a GPU (Part 3).

  4. Your answers are in that file on your own computer. To hand the lab in, follow the instructions in its Canvas quiz: the quiz asks for the numbers your notebook produced, not for the file itself.

Part 3: Run a lab on a GPU, from VS Code

Google’s Colab extension for VS Code (released November 2025) lets a notebook that is open in VS Code run on a Colab machine:

  1. Open the downloaded notebook in VS Code (Part 2). (Older links in Canvas may still send you to a page that asks for the path of a cloned folder; you can ignore it and open the file directly.) The first time, the page that opens asks for the full path of your kb8029-book folder (for example C:\Users\you\kb8029-book or /Users/you/kb8029-book) and remembers it; after that, its button opens the notebook straight in VS Code. You can also open it yourself: in VS Code press Ctrl+P (Cmd+P on a Mac) and type the notebook’s name, for example session04-lab.ipynb.

  2. Click Select Kernel (top right) → Colab → Auto Connect (or choose a runtime with a GPU), and sign in with your Google account when asked.

  3. Run the first cells. Most notebooks start with an install cell, which installs the few packages that Colab does not already have (for example Biopython); this takes a few seconds each time you connect to a new machine.

  4. When you need a GPU (mainly Sessions 9-12), check that you got one:

    import torch
print(torch.cuda.is_available(), torch.cuda.get_device_name(0) if torch.cuda.is_available() else "")

Your changes are saved in your own copy of the notebook in kb8029-book. If Git: Pull complains that a file you changed would be overwritten, keep your version under another name (for example session04-lab-mine.ipynb) and pull again.

Things to know:

  • The code runs on Google’s machine. It cannot see files on your laptop, even though the notebook file is open in VS Code. The course notebooks download what they need from the course’s GitHub repository, so they work anyway. For your own files, upload them, or mount Google Drive (Command Palette → Colab: Mount Google Drive to Server…).
  • Colab machines are temporary. Everything on them, including installed packages and files the notebook wrote, disappears when the session ends. Your notebook itself, with its code and output, is saved on your laptop by VS Code. Save other results you want to keep (download them, or write them to Drive).
  • The free GPU is limited. A session is closed after a period of inactivity or when your quota is used up, and a GPU is not always available. Ask for a GPU only when the notebook needs one, and when you are done, release the machine with Colab: Remove Server.
  • No terminal tools. Everything in the labs is done from Python: the sequence searches and alignments in Sessions 4 and 5 call EMBL-EBI’s web services (HMMER, Clustal Omega, InterPro), and in Session 6 PyMOL runs inside the notebook and structure searches go to the Foldseek web service.

The course notebooks that go with each session page work exactly the same way as a lab (Part 1), and can equally be opened from your kb8029-book folder in VS Code.

Part 4 (optional): Get every course notebook in one go

  1. Click Clone the course notebooks into VS Code. Your browser asks whether to open VS Code: allow it. (Or, in VS Code: Command Palette, Ctrl+Shift+P or Cmd+Shift+P → Git: Clone → https://github.com/ElofssonLab/kb8029-book.git.)
  2. Choose where to save the folder kb8029-book (about 100 MB), and open it when VS Code offers to. The notebooks are in its notebooks folder.
  3. Before each lab, get the latest version: Command Palette → Git: Pull. The teachers sometimes fix a lab shortly before it is used.

Troubleshooting

Clicking the lab link shows the notebook as text instead of saving it. Save it yourself: right-click the link → Save link as…, and keep the name ending in .ipynb.

I cannot find the file I downloaded. It is in your browser’s download folder, normally Downloads. In VS Code, File → Open File… and go there.

VS Code opens the notebook as a wall of JSON. That is the raw file. Close it and reopen with Open With… → Jupyter Notebook, and check that the Jupyter extension is installed (Part 1).

VS Code does not offer Colab under Select Kernel. Check that the Google Colab extension is installed and enabled in a local VS Code window, and reload the window (Command Palette → Developer: Reload Window).

ModuleNotFoundError. The runtime is new and the install cell has not been run in it. Run the notebook from the top.

FileNotFoundError for a file you can see on your laptop. You are running on a Colab kernel (Part 3), not locally, so the code cannot see your disk: upload the file, read it from Drive, or switch back to your local Python kernel.

No GPU, or torch.cuda.is_available() is False. You were given a machine without a GPU, or the free GPU quota is used up for now. Choose a GPU runtime explicitly, try again later, or run the notebook on the CPU: the course notebooks are small enough for that, only slower.

The connection drops in the middle of a long cell. Colab closes idle and long-running free sessions. Reconnect, run the notebook from the top, and save intermediate results to Drive if a step takes long.
